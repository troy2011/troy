# 特殊能力判定の運用

## 公開前の状態

特殊能力判定は既定で無効です。通常の店舗占いURLを開いても入口は表示されません。

有効化にはRenderの環境変数へ次の3件を設定します。

- `SPECIAL_ABILITY_ENABLED=true`
- `SPECIAL_ABILITY_SIGNING_SECRET`: 判定データ署名用の十分に長いランダム文字列
- `SPECIAL_ABILITY_TERMINAL_TOKEN`: 店舗端末確認用の24文字以上のランダム文字列

## 店舗端末の登録

店舗端末では、次の形式のURLを一度開きます。

```text
https://troy-xetw.onrender.com/tarot-reading.html?abilityTerminal=<SPECIAL_ABILITY_TERMINAL_TOKEN>
```

トークンはURL欄から直ちに消え、端末のタブ内へ12時間有効なセッションとして保存されます。トークン付きURLは一般公開せず、店舗端末の初期設定だけに使います。

## 保存と公開範囲

- 判定が正常に確定した時だけ、一人一回を消費します。
- 判定途中の回答はFirestoreへ保存しません。
- PlayFabの公開ReadOnly Dataには確定した能力を保存します。
- 他人のプロフィールへ表示する情報は「性格タイプ」「4軸の日本語表現」「系統」「能力名」「横文字名」「能力効果」「発動条件」です。
- 回答内容、反応時間、軸ごとの採点値、英字の系統コードはAPIから返しません。
- 既存のV3判定結果に性格タイプが保存されていない場合、店舗で判定履歴を確認した時にFirestoreの確定記録からPlayFabへ一度だけ補完します。

## 能力カタログ

- 365件の能力名、横文字名、効果、発動条件、最適性格型、判断速度適性は能力ごとに個別設計し、配列順や共通テンプレートでは割り当てません。
- 効果は「何ができるか」、発動条件は「何をすれば使えるか」が一度で分かる固有の一文に限定します。
- 重複回避は適性順位の上位3件だけを対象にし、割当回数を理由に適性の低い能力へ落としません。
- 既存の判定結果も能力IDから現行カタログを参照するため、文章改訂が公開プロフィールへ反映されます。

## 内容更新時の確認

```powershell
npm run special-ability:generate
npm run special-ability:audit
npm run special-ability:quality
npm run special-ability:test
```

監査は365能力、能力設計台帳との完全一致、横文字名の欠落・重複・借用、固有の発動条件、適性型と速度分布、16タイプと33系統組み合わせ、12問48画像、画像寸法と重複、能力文の重複と類似を検査します。品質ゲートは全能力を明瞭さ、系統整合、発動条件、独自性、話しやすさの10点満点で採点し、9点未満が一件でもあれば失敗します。
